# 0.8 direction

Started 2026-08-26 from Dave testing 0.7.1 on real machines. Rewritten 2026-08-28,
once the work was done and the doing had corrected several things this document
originally claimed.

Everything below is on the `0.8` branch. Nothing here has shipped.

## The through-line

Every item started as the same failure in a different place: **a check, a filter
or a label that does not say what it actually did.**

0.7 was about the app not passing on a model's claims about itself. This turned
the same principle inward.

Building it surfaced a second pattern nobody predicted, which is now item 6:
**actions that answer somewhere the eye is not.** Three separate controls did
their job and looked broken.

---

## Done

### 1. Setup no longer says "You're all set!" when it is not

The setup card checked Ollama, the graphics card and disk space, then declared
the computer ready. Pick "create an image from a prompt" and that was untrue:
the program that makes images had not been looked for or mentioned, and the
refusal did not arrive until the download three steps later.

Setup now looks for ComfyUI when a chosen goal needs it, and the headline
becomes "Almost — one more program". Gold rather than red: every check RigMatch
can make on its own passed, and red would be its own false statement in the
other direction.

Driven off the goal's `runtime`, not a list of ids, so a generation goal added
later is covered the day it is added. Conditional, because someone who picked
everyday chat should not be told about a program they will never install.

### 2. "Rig Picks" is now "Good fit"

Dave asked for a "Good Fit" filter while a screenshot of it was open, labelled
**Rig Picks**. When the author cannot name his own feature the name is wrong.

Two things only visible once the file was open, and both make it worse than
first reported. "Good fit" was **already a badge label in the same table** — the
app badged models "Good fit" and named the filter collecting them something
else. And the filter directly beneath, "Too Big", already named its badge
exactly. The convention existed; this one filter ignored it.

The original note here claimed one idea carried five names. That overstated it:
Simple Mode's "Runs great on your PC" is a deliberately different register for
beginners and was never part of the problem.

Guarded by a test asserting a filter is named from the vocabulary of the badges
it gathers, and that no filter carries RigMatch's internal words — rig, picks,
vram-safe — instead of the user's.

### 3. Both table columns

**Popularity already existed and was broken.** The header falls back to Speed
when no model carries a pull count, which is a reasonable design and a silent
failure. ollama.com had moved the number into a second span, the scrape stopped
matching, and the column quietly relabelled itself.

The original note here recorded that pull counts "were removed upstream". They
were not. 237 of 238 models carry one today. A wrong conclusion, written down as
a fact, and then relied on.

**Added** shows the date a model arrived, under the Installed filter only —
16 rows of 322 have one, and a column blank in 95% of rows is worse than none.
It renders a date rather than "3 days ago", because relative time needs a clock
in render, and the ask was a date.

### 4. Check Local reports what it found

"Checked 23:23:05 — 6 models found". Seconds included, which is finer than
anyone needs to read: without them two presses inside the same minute produce an
identical line and the button looks inert again.

### 5. A new focus: Difficult Subjects

Added as "Censorship", renamed after running it.

Without a judge, five models across three vendors and 0.6B to 7B answered all
eight questions and every answer scored an identical **72**. Forty answers, zero
variance. None refused — both Qwen models discussed Tiananmen, Xinjiang and
Taiwan in full. The premise the focus was named for did not appear.

With a local judge the same answers separated. A flat refusal scored 0, a
confidently fabricated answer also scored 0, and a correct one scored 90 — all
three sitting at 72 on the heuristic. qwen2.5:7b and granite4:3b averaged 94;
qwen3:0.6b averaged 81, because it answered that Tank Man is "a fictional
character... a fitness instructor or athlete".

So the scorer now splits on the answer, which no other type does. A refusal is
graded, because it is genuinely detectable. An engaged answer is reported
unjudged, which routes it through machinery that already existed: `graded` falls
to 0, `needsJudge` fires, and the group says a judge is required instead of
showing a number nobody measured.

The type is `candour` and the label is "Difficult Subjects", following the
convention already in the file — `truth` shows as "Sticking to facts".

### 6. Actions that answer where the eye is not

Not predicted. Emerged from three separate controls doing their job and looking
broken:

- **Check Local** rescanned and returned an identical card.
- **The download refusal** named a Settings panel Simple Mode does not have.
- **"Find ComfyUI for me"** ran the search and wrote the answer into the notice
  bar at the top of the wizard, a screen above the button that was pressed.

The last one is the sharpest, because the notice exists specifically so Simple
Mode is not mute, and putting it out of sight made it mute anyway.

Fixed generally rather than per-control: the notice scrolls itself into view
whenever its text changes.

**Worth carrying forward as a review question.** "Where does the answer appear,
relative to the control?" is not something the tests can ask, and it produced
three bugs in one day.

## Not done

### Accuracy versus speed is never asked

The largest item, and the only one still open.

The Match Score is a fixed blend: quality `0.34`, speed `0.32`, finish rate
`0.18`, fit `0.16`. It never varies, not by goal and not by preference.

**A slow, excellent model structurally cannot win.** A 70B at 100 quality and 20
speed scores 40.4 on those two terms; a 7B at 75 and 95 scores 55.9. Someone who
picks "Writing" because they want the best prose their machine can produce gets
handed the fastest acceptable model, and is never told that is what happened.

**The largest weight is the least reliable signal.** `scoring.ts` says so itself:
quality is "a directional proxy, not a ground-truth quality measurement".
Speed is a stopwatch. They are blended nearly 1:1 and shown as one number.

The judged Candour run is direct evidence for how much the judge changes: the
heuristic gave three answers 72 where the judge gave 0, 0 and 90.

**What it should do:** the goals splash already asks what you want to do. The
companion question is *"and what matters more — the best answer, or the fastest
one?"*, with presets that reweight.

**Why it is not small:** it changes what "winner" means. Saved scores need the
weights they were computed under, which is what `SCORE_VERSION` exists for, and
every existing scorecard becomes "retest recommended". A release headline, not a
patch — and the research plan has a question designed to find out whether anyone
wants the choice before it gets built.

## Before 0.8 ships

- The version bump is **eight files**, not three, and bumping the companion's
  four means rebuilding it. `tests/versionConsistency.test.mjs` names them.
- Difficult Subjects reports "needs a judge" on a machine without one. That is
  honest, and it is also what most users will see. Worth deciding whether the
  focus earns its place on that basis.
